# OASIS — Open Autonomous System for Intelligent Swarms

> Transform Claude Code into a self-evolving multi-agent orchestration platform. 16 specialized agents, 160 skills, complexity-based task routing, anti-drift protection, and persistent memory — all running from markdown files.

---

## What This Does

OASIS turns a single AI coding assistant into a coordinated team of specialists. When you give it a task, the system:

1. **Routes** the task to the right agent(s) based on complexity and domain
2. **Plans** using structured methodology (SPARC) for complex work
3. **Executes** with anti-drift monitoring, checkpoints, and permission enforcement
4. **Learns** from every session — patterns, mistakes, and reflections persist across conversations

No custom runtime. No compiled binaries. Just markdown files, Python scripts, and a config.toml that any Claude Code, Gemini CLI, or VS Code AI agent can read.

## Core Systems

### Intelligent Task Routing

Every task is automatically classified by complexity and routed to the optimal agent(s).

| Complexity | What Happens | Agents Assigned |
|-----------|-------------|-----------------|
| **Trivial** (1 file, 1-2 steps) | Handled inline | None — direct execution |
| **Simple** (1-2 files) | Single specialist | Domain-matched agent |
| **Moderate** (3-5 files) | Agent + review gate | Primary agent → reviewer |
| **Complex** (6-15 files) | Full team, plan required | Architect → writer → reviewer → debugger |
| **Architectural** (15+ files) | SPARC methodology enforced | Full team + user approval at each phase |

Domain detection scans for keywords (security, database, content, revenue, etc.) and overrides the default routing when a specialist is clearly needed.

Config: `.agents/config.toml` → `[routing]`

### Anti-Drift Protection

Agents working on complex tasks will drift from the original intent. Three detectors prevent this:

- **Scope Creep Detector** — Flags when files touched exceed the plan by 3+
- **Error Cascade Detector** — Stops after 2 consecutive failures, forces approach switch (no more retrying the same broken thing 5 times)
- **Time Overrun Detector** — Checkpoints when task exceeds 2x estimated duration

Every 5 task steps, the agent must validate: "Am I still on track?" If not, it re-aligns or escalates.

Config: `.agents/config.toml` → `[anti_drift]`

### SPARC Methodology

For complex implementations, the system enforces 5 sequential phases:

```
Specification → Pseudocode → Architecture → Refinement → Completion
```

Each phase has required outputs and approval gates. Code cannot be written until the spec and architecture are approved. This eliminates the "I built the wrong thing" problem.

Config: `.agents/config.toml` → `[sparc]`

### Claims-Based Agent Permissions

Not every agent should touch every file. Four permission levels enforce least-privilege:

| Level | Claims | Example Agents |
|-------|--------|----------------|
| **minimal** | read only | explorer, researcher |
| **standard** | read, write, execute | writer, reviewer, documenter |
| **elevated** | + spawn agents, access memory | architect, debugger |
| **admin** | all permissions | Lead orchestrator only |

Universal blocked patterns (`.env*`, `*.pem`, `*.key`) apply to ALL agents regardless of level.

Config: `.agents/config.toml` → `[permissions]`

### 10-Step Reasoning Protocol (Brain Loop)

Every significant task passes through a structured reasoning cycle:

```
ORIENT → RECALL → ASSESS → PLAN → VERIFY → EXECUTE → REFLECT → STORE → EVOLVE → HEAL
```

Key features:
- **Multi-hypothesis generation** — For moderate+ tasks, generate 2-3 approaches and rank them (LATS-inspired)
- **Activation-scored retrieval** — Memory recall prioritized by recency (0.3) + frequency (0.4) + confidence (0.3)
- **Structured Reflexion** — On failure, generate a formal analysis: what was attempted, what went wrong, why, and what to do differently (Shinn et al., 2023)
- **Confidence decay** — Facts not re-verified lose confidence over time: C(t) = C₀ × e^(-λt)

### Background Workers

Four automated workers maintain system health during active sessions:

| Worker | Priority | Interval | Purpose |
|--------|----------|----------|---------|
| **Audit** | Critical | 5 min | Secret scanning, credential file checks, permission verification |
| **Memory** | High | 30 min | Bloat prevention, confidence decay, duplicate detection |
| **Sync** | High | 10 min | Cross-agent state synchronization, Supabase trace flushing |
| **Optimize** | Low | 60 min | Unused skill detection, referential integrity, pattern promotion |

### Self-Improvement Loop

The system learns from every session:

```
Success → Extract pattern → Tag [PROBATIONARY] → Validate across 3 sessions → Promote to [VALIDATED]
Failure → Generate Reflexion entry → Store for future RECALL → Prevent recurrence
Repeated process → Auto-generate SOP → Track execution count + success rate
```

Patterns, mistakes, and reflections persist in markdown files AND optionally in Supabase for cross-session semantic search.

### Cross-AI Synchronization

Three AI interfaces share the same intelligence:

| Interface | Entry Point | Strength |
|-----------|------------|----------|
| **Claude Code** | `CLAUDE.md` | Complex refactoring, architecture, system evolution |
| **Gemini CLI** | `GEMINI.md` | Fast diagnostics, research, content generation |
| **VS Code AI** | `ANTIGRAVITY.md` | IDE-native chat with full MCP access |

All three write to the same `brain/STATE.md`, `memory/SESSION_LOG.md`, and `memory/ACTIVE_TASKS.md`. Switch mid-task with zero context loss.

## Quick Start

```bash
# 1. Clone the repo
git clone https://github.com/CC90210/Business-Empire-Agent.git
cd Business-Empire-Agent

# 2. Set up credentials
cp .env.agents.template .env.agents
# Fill in your API keys (Supabase, Stripe, n8n, etc.)

# 3. Install dependencies
npm install

# 4. Start with any AI interface
# Claude Code reads CLAUDE.md automatically
# Gemini CLI reads GEMINI.md
# VS Code AI reads ANTIGRAVITY.md via .vscode/mcp.json
```

The agent loads its brain silently, routes your task to the right specialist, and starts working. Session state is saved automatically so any AI interface can pick up where the last one left off.

## Configuration

All orchestration settings live in one file: `.agents/config.toml`

| Section | What It Controls |
|---------|-----------------|
| `[routing]` | Complexity thresholds, agent assignments, domain overrides |
| `[anti_drift]` | Checkpoint intervals, scope limits, error cascade detection |
| `[permissions]` | Per-agent access levels, file scope restrictions, blocked patterns |
| `[sparc]` | Development phase requirements and approval gates |
| `[performance]` | Max agents, timeouts, memory budgets, caching |
| `[workers]` | Background worker intervals and task definitions |
| `[hooks]` | Pre/post operation automation and learning triggers |
| `[security]` | Input validation, secret scanning, blocked file patterns |

## Contributing

This system is designed to be forked and adapted. The architecture is modular:

- **Add a new agent:** Create `agents/your-agent.md`, register in `brain/AGENTS.md`
- **Add a new skill:** Create `skills/your-skill/SKILL.md` with YAML frontmatter
- **Add a workflow:** Create `.agents/workflows/your-command.md`
- **Tune behavior:** Edit `.agents/config.toml` — all thresholds are configurable

The meta-agent (`agents/meta-agent.md`) can generate new agent definitions from natural language descriptions.
