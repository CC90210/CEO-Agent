📜 CLAUDE.md — Your AI's Instruction Manual

XP Reward: +100 XP | Running Total: 275 XP

Level: Builder (L1) — Configuring your AI employee for maximum output.

CLAUDE.md is the single most important file in any Claude Code project. It's a markdown file that lives in your project root and tells Claude Code how to behave in this specific project. Without it, Claude is a genius with amnesia. With it, Claude is YOUR genius with perfect context.

⚡ QUICK WIN: Think of CLAUDE.md like onboarding instructions for a new hire — except this hire has perfect memory, follows instructions exactly, and never calls in sick. The better your instructions, the better your employee.

📋 What Goes in CLAUDE.md

🏗️ Project Context — What is this project? What tech stack? What's the goal?

📏 Rules & Constraints — "Never delete the database." "Always use TypeScript." "Test before committing."

🔀 Tool Routing — "Use Supabase for database queries." "Use Playwright for web browsing."

🎨 Style Preferences — "Use conventional commits." "Keep functions under 50 lines."

🚫 Don'ts — "Don't create new files unless necessary." "Don't hardcode API keys."

💡 PRO TIP: Start with 10 lines. Add rules as you discover what Claude gets wrong. A 10-line CLAUDE.md that covers the essentials beats a 200-line novel that dilutes the important stuff. Think of it like a recipe — the best ones are concise.

🧬 Starter Template

# Project Name

## What

- Project: [name and purpose]

- Stack: [languages, frameworks, databases]

- Deploy: [where it's hosted]

## Rules

1. Always write tests before code

2. Use conventional commit messages

3. Never hardcode secrets — use .env

## Don'ts

- Don't delete files without asking

- Don't push to main directly

That's a complete, functional CLAUDE.md. Copy it, customize it, and your AI employee immediately understands your project.

🔍 How Claude Reads It

Claude Code automatically loads CLAUDE.md every conversation. It checks three levels:

1️⃣ Project root — ~/your-project/CLAUDE.md (always loaded first)

2️⃣ Parent directories — ../CLAUDE.md (inherited rules from above)

3️⃣ User-level — ~/.claude/CLAUDE.md (your global preferences)

This hierarchy means you can set global rules (like "always use TypeScript") at the user level, and project-specific rules (like "this project uses Python") at the project level. Project rules override global ones.

📎 @Imports — Referencing Other Files

Use @imports to reference other files: @docs/api-reference.md pulls content into context on demand. This keeps your CLAUDE.md lean while giving Claude access to detailed documentation.

Common @import patterns:

• @docs/api-reference.md — API documentation

• @brain/STATE.md — Current project state

• @skills/debugging/SKILL.md — Load a skill on demand

💀 COMMON MISTAKE: Importing everything. Each @import adds to Claude's context window. Only import what's needed for the current project — not your entire documentation library.

🏗️ Advanced CLAUDE.md Patterns

Decision Framework: Tell Claude how to make choices for you:

## Decision Protocol

- For simple tasks: just do it (Fix-First principle)

- For moderate tasks: brief plan, then execute

- For complex tasks: present options, wait for approval

MCP Routing: Tell Claude which tools to use for what:

## Tool Routing

| Task | Tool |

| Database queries | Supabase MCP |

| Web browsing | Playwright MCP |

| Social media | Late MCP |

Security Rules: Non-negotiable constraints:

## Security (CRITICAL)

- NEVER hardcode API keys or passwords

- All secrets in .env.agents (gitignored)

- Validate all inputs at system boundaries

- Confirm before any destructive operation
