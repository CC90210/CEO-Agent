🏗️ The CLI Engine Pattern

Every tool in our stack follows the same structure. Learn this once and you can read, extend, or build any of the 11 engines.

The pattern: one Python file, multiple subcommands, JSON output, credentials from environment, Supabase as the database.

Every engine is called from the terminal like this:

python scripts/lead_engine.py list

python scripts/lead_engine.py add --name "Sarah Chen" --email "s@example.com"

python scripts/lead_engine.py score --id 42

python scripts/lead_engine.py pipeline --stage qualified

Every engine supports --json output for machine consumption:

python scripts/lead_engine.py list --json | python -m json.tool

⚡ QUICK WIN: This --json flag is what allows Claude Code, the scheduler, and other engines to talk to each other. It turns a human-readable CLI tool into an API. Add it to every tool you build.

🔬 Anatomy of an Engine

Here is the exact skeleton every engine follows. Read this carefully — the rest of the course assumes you know this structure.

1. Imports

import argparse, os, json, sys

from datetime import datetime

from dotenv import load_dotenv

from supabase import create_client

2. Environment loading

load_dotenv('.env.agents')

SUPABASE_URL = os.environ['SUPABASE_URL']

SUPABASE_KEY = os.environ['SUPABASE_SERVICE_KEY']

⚠️ WARNING: Always use os.environ['KEY'] — not os.environ.get('KEY'). The difference: get() silently returns None when a key is missing, which causes cryptic errors later. Hard brackets raise an immediate, clear KeyError so you know exactly what's wrong.

3. Supabase client

supabase = create_client(SUPABASE_URL, SUPABASE_KEY)

4. Subcommand functions

Each subcommand is a function that takes parsed args and returns either a dict or prints output. Business logic lives here.

def cmd_list(args):

result = supabase.table('leads').select('*').limit(args.limit).execute()

if args.json:

print(json.dumps(result.data, indent=2))

else:

for lead in result.data:

print(f"{lead['id']:>4} | {lead['name']:<30} | {lead['stage']}")

5. Argument parser

def build_parser():

parser = argparse.ArgumentParser(description='Lead Engine')

parser.add_argument('--json', action='store_true')

subs = parser.add_subparsers(dest='command')

p_list = subs.add_parser('list')

p_list.add_argument('--limit', type=int, default=20)

p_list.set_defaults(func=cmd_list)

return parser

6. main()

if __name__ == '__main__':

parser = build_parser()

args = parser.parse_args()

if not args.command:

parser.print_help()

sys.exit(1)

args.func(args)

💀 COMMON MISTAKE: Putting business logic directly in main(). Each subcommand must be its own function. When Claude Code extends your engine later, it adds a new function and a new add_parser call. Nothing else changes. That's the design.

🛠️ Prerequisites & Environment Setup

You need these before anything else works:

Software

• Python 3.12 or higher — python --version to verify

• pip — comes with Python

• A Supabase account (free tier is enough) — supabase.com

• Git

Python dependencies

pip install supabase python-dotenv requests

The .env.agents file

Create this file in your project root. It never gets committed to git:

SUPABASE_URL=https://your-project-id.supabase.co

SUPABASE_SERVICE_KEY=your-service-role-key-here

SUPABASE_ANON_KEY=your-anon-key-here

Find these values in your Supabase dashboard under Settings → API.

⚠️ WARNING: Use the service role key (the long one labelled service_role), not the anon key. The service role key bypasses Row Level Security, which your CLI tools need to run without a user session. The anon key is for client-side browser code. Keep them straight.

Add .env.agents to your .gitignore immediately:

echo ".env.agents" >> .gitignore
