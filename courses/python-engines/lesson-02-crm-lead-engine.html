🗄️ Database Schema

Two tables. That's the entire CRM.

Table: leads

id — bigint, primary key, auto-increment

name — text, not null

email — text

phone — text

company — text

source — text (instagram, referral, cold-outreach, inbound, etc.)

stage — text, default 'new' (new → contacted → qualified → proposal → negotiating → won/lost)

score — integer, default 0

notes — text

assigned_to — text

next_followup — timestamptz

created_at — timestamptz, default now()

updated_at — timestamptz, default now()

Table: lead_interactions

id — bigint, primary key, auto-increment

lead_id — bigint, foreign key → leads.id

type — text (email_sent, email_opened, email_clicked, call, meeting, dm_reply, proposal_sent, note)

notes — text

created_at — timestamptz, default now()

⚡ QUICK WIN: Create both tables in the Supabase SQL editor with one query. Open your Supabase project → SQL Editor → paste the CREATE TABLE statements → run. Takes 60 seconds. Every other engine in this stack also starts with schema creation — get comfortable with it now.

🔧 All Commands

Here is the full command surface of lead_engine.py:

list — Show all leads with optional filtering

python scripts/lead_engine.py list

python scripts/lead_engine.py list --stage qualified

python scripts/lead_engine.py list --limit 10 --json

add — Create a new lead

python scripts/lead_engine.py add --name "Sarah Chen" --email "s@acme.com" --company "Acme Corp" --source instagram

view — Show a single lead with full interaction history

python scripts/lead_engine.py view --id 42

update — Update any field on an existing lead

python scripts/lead_engine.py update --id 42 --stage qualified --notes "Confirmed budget of $2K/mo"

score — Recalculate and display the lead score

python scripts/lead_engine.py score --id 42

interact — Log an interaction (automatically increments score)

python scripts/lead_engine.py interact --id 42 --type meeting --notes "45-min discovery call, very interested"

pipeline — Show all leads grouped by stage with counts

python scripts/lead_engine.py pipeline

followups — Show leads where next_followup is overdue or due today

python scripts/lead_engine.py followups

funnel — Conversion rates between each stage

python scripts/lead_engine.py funnel

📊 Lead Scoring Algorithm

Every lead has a score. Score determines priority. Here are the exact point values:

Profile completeness (base score):

• Email on file: +10 points

• Phone on file: +10 points

• Company on file: +5 points

Interaction history (+points per occurrence):

• Any interaction logged: +5 points

• email_opened: +10 points

• email_clicked: +15 points

• meeting: +20 points

• dm_reply: +15 points

A lead who replied to a DM, booked a meeting, and clicked a follow-up email has: 10 (email) + 10 (phone) + 5 (company) + 15 (dm_reply) + 20 (meeting) + 15 (email_clicked) = 75 points. That is a hot lead. Work that lead today.

The scoring function queries lead_interactions and sums weights. It runs on score command and automatically after every interact call.

💡 PRO TIP: The scheduler runs lead_engine.py followups --json every morning at 8AM and sends the list to Telegram via notify.py. You wake up with your priority call list already in your phone. Set this up in Lesson 4.

🔄 Pipeline Stages

Every lead flows through these stages in order:

new → Lead entered the system, no contact made yet

contacted → First outreach sent (DM, email, or call)

qualified → Confirmed fit: budget, authority, need, timeline

proposal → Proposal or pricing sent

negotiating → Actively discussing terms

won → Signed. Move them to your client list.

lost → Not proceeding. Log why with a note. Review monthly.

Move a lead between stages:

python scripts/lead_engine.py update --id 42 --stage proposal

The pipeline command shows a visual breakdown of how many leads are in each stage and what your bottleneck is. If you have 20 leads in qualified but only 2 in proposal, you are not sending enough proposals. The data tells you where to focus.

🔗 Integration Points

The lead engine does not operate in isolation. It connects to the rest of the stack:

email_engine → lead_engine: When email_engine.py send delivers an email to a lead, it calls lead_engine.py interact --type email_sent automatically. Every send is logged. You never lose track of who got what.

booking_engine → lead_engine: When a booking is confirmed, booking_engine.py calls lead_engine.py update --stage contacted on the matching email. Stage advances automatically.

instagram_engine → lead_engine: DM replies captured by instagram_engine.py can be piped into lead_engine.py interact --type dm_reply. Score updates automatically.

notify.py: Every time a lead moves to qualified or won, the lead engine fires a Telegram notification via notify.py. You get pinged on your phone the moment a deal closes.

💀 COMMON MISTAKE: Logging interactions manually after the fact. The value of this system is automatic, real-time logging. Wire up the integrations in Lesson 4 and let the engines talk to each other. If you are manually logging every email send, you have rebuilt HubSpot's worst feature: data entry.

🧠 KEY TAKEAWAY: A CRM is only as useful as the data inside it. The lead engine is designed so that data enters automatically — through email sends, booking confirmations, and DM replies — without you typing anything. Your job is to run the pipeline and followups commands each morning, not to maintain the database.
