🧪 End-to-End Testing Skills

Combine browser automation with testing to build skills that test your actual application:

E2E Test Skill:

---

description: Full end-to-end test of the application

---

1. Start the dev server (npm run dev)

2. Navigate to each page with Playwright

3. Test every form, button, and interaction

4. Check console for JavaScript errors

5. Test at mobile (375px), tablet (768px), desktop (1440px)

6. Screenshot any issues found

7. Fix issues, re-test, report results

This single skill replaces manual QA testing. Run it before every deployment. Catch bugs before your users do.

📋 Plan-Execute Skills

For complex features, break the work into two phases:

Phase 1: Plan

---

description: Create implementation plan for a feature

---

Feature: $ARGUMENTS

1. Analyze the codebase for relevant files

2. Identify dependencies and integration points

3. Break into numbered tasks (each 2-5 minutes)

4. Include test strategy for each task

5. Save plan to docs/plans/ directory

6. Wait for approval before executing

Phase 2: Execute

---

description: Execute an approved plan step by step

---

Load the plan from docs/plans/

Execute tasks in order:

- Write failing test first

- Implement minimal code to pass

- Verify before moving to next task

- Commit after each completed task

Stop and report after every 3 tasks.

🧠 KEY TAKEAWAY: Plan-Execute is how you build features that would normally take days. The plan prevents Claude from going off-track. The execute phase follows a verified path. Combined with TDD, you get reliable code at AI speed.

🔗 Skill Chaining — The Pipeline Pattern

The real power is chaining skills into pipelines. Here's a full ship pipeline:

1️⃣ /plan → Break feature into tasks

2️⃣ /execute → Build with TDD

3️⃣ /review → Auto-fix mechanical issues, flag judgment calls

4️⃣ /commit → Conventional commit message

5️⃣ /ship → Build check, push, deploy verification

Each skill is simple on its own. Chained together, they form a complete software delivery pipeline. One person with these skills ships faster than a team of 5 without them.

⚠️ WARNING: Don't build a pipeline skill that calls other skills internally — Claude Code doesn't support nested slash commands. Instead, run them in sequence manually. The discipline of running each step keeps you in control.

🏗️ Building Skills from Experience

The best skills come from your own repeated tasks. Follow this pattern:

Step 1: Notice you're doing something for the 3rd time

Step 2: Write down the steps you followed

Step 3: Turn those steps into a skill file

Step 4: Test it, refine it, use it

After 3 uses, review the skill — are there steps you always skip? Remove them. Steps you always add? Include them. Skills evolve.

💀 COMMON MISTAKE: Building skills for things you'll only do once. Skills are for repeated workflows. If you're not going to use it again, just write the prompt directly. Don't over-engineer your toolbox.
